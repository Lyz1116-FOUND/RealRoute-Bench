# Method coverage and admission plan

The following is a planned coverage taxonomy, not a claim that every method has been run. The custom heuristic remains withdrawn from public results.

### 6.4 正式测评必须覆盖完整方法谱系

项目目标不是只给 LLM 配几个参照算法。只要一种方法在规定条件下能够消费公开任务、保留其完整语义并输出可检查的解，就应纳入候选登记和测评；精确方法、启发式、神经方法和 LLM 都是研究对象。

“能测的都测”需要落到有限、可复核的方法清单：登记实现和版本，审计支持范围，在其全部合格任务上按预先冻结的预算运行，并记录未完成或被拒原因。不能声称穷尽未来所有算法，也不能把现有三方法 reference 批次完成叫作全方法测评完成。

| 方法类别 | 应覆盖的候选条件 | 当前实际状态 | 必须回答的问题 |
|---|---|---|---|
| 精确求解 | 当前 HiGHS MILP；有许可/可复现条件时的 Gurobi、SCIP、CPLEX 等候选；必要时问题专用 branch-and-cut 或其他精确实现 | HiGHS 已进入全静态批次；Gurobi 当前被排除；其余未核验接入 | 限时可行率、证优率、目标界、gap 随时间变化；不同建模/后端如何影响结果 |
| 基础构造与局部搜索 | 最近邻、便宜/后悔插入、多起点构造；relocate、swap、适合有向问题的路线交换等 | 已有 greedy 和 LNS 内部构造；未形成各操作独立的全量比较表 | 简单方法能达到什么程度，改进来自初始化、邻域还是更多预算 |
| 轨迹型元启发式 | LNS/ALNS、迭代局部搜索、禁忌搜索、模拟退火等 | 自研 LNS 已撤下对外成绩；文献算法或外部实现尚待登记/复现 | 不同搜索机制的质量、稳定性、收敛与约束覆盖 |
| 种群与专业路由算法 | 遗传/混合搜索、专业 VRP 库与问题专用算法；固定版本 PyVRP 条件 | PyVRP 已适配并训练诊断；尚无覆盖所有合格静态题的正式横向表 | 专业方法相对通用搜索的增益及支持边界 |
| 通用路由/约束工具 | OR-Tools Routing GLS；有明确语义和预算绑定时的其他搜索/约束编程候选 | GLS 已适配和诊断；新组合批次纳入部分合格作业 | 通用工具可覆盖哪些问题，失败来自能力、初始化还是时限 |
| 神经构造算法 | 图/注意力编码与自回归路线策略、强化学习或模仿学习构造、多起点/对称性策略等候选 | 尚无可纳入当前主表的正式结果；实现、权重和任务适配待验收 | 是否学会成本与约束结构，换城市、规模和组合后是否保持可行 |
| 神经改进与搜索 | 学习选邻域/破坏修复、neural improvement、learned LNS、神经候选与搜索结合 | 待登记、复现和预算绑定 | 增益来自学习还是额外传统搜索；是否优于同预算纯启发式 |
| LLM | Direct 与声明式 Model；模型家族、服务条件和重复分别登记 | 已有若干开发调用和 Spark 64 次小样；多模型正式表未完成 | 理解、合同、约束、求解质量、采样稳定性和资源成本 |
| 混合方法/系统 | LLM 或神经模型+固定 solver/搜索；工具型 Agent；未来状态预测+路由 | Model 已有小样；Agent 和预测轨尚未正式完成 | 系统增益由哪一模块产生，能否在相同资源下复现 |

表中的未接入方法是候选工作范围，不宣称库已经安装、模型权重可用或某个实现已支持全部任务。算法名称、库产品和具体实验条件也不是同一个统计层级：同一求解器的不同 formulation、同一模型的不同训练或搜索预算，应作为明确的条件记录。

### 6.5 先建立“问题×方法”支持矩阵

对 11 个经典模板、6 个旧组合预设及 25 个新组合族，都需要逐实例做能力准入。最低限度应区分以下任务块：

| 任务块 | 需要逐项核验的适配问题 |
|---|---|
| 有向 TSP/基本配送 | 是否读取完整非对称矩阵；是否偷偷换成欧氏距离；终端与节点计数是否一致 |
| 容量与异构车队 | 逐车容量、启用成本、使用车辆数上限；是否误用默认字典序目标 |
| 时间窗与时长 | 秒制时间、等待、服务开始窗、固定发车、终端窗、服务时间和时长上限 |
| 开放路线/多仓库 | closed、fixed、free 是否区分；真实终端矩阵是否保留 |
| 取送与一般关系 | 成对选择、同车、先后、全过程载荷、同/异车条件是否完整 |
| 可选访问与收益罚金 | 选择逻辑、收益方向、最低收益、漏访罚金与权重、合法空解 |
| 多资源及新交互 | 成本预算、物理距离限制、车辆数限制与其他原子共同启用时是否仍保真 |

如果神经模型只接受坐标和欧氏代价，就不能直接用坐标近似替换真实有向矩阵后声称完成本题；如果只学过单仓库 CVRP，也不能把关系、开放终点或收益罚金删掉后计入全任务成功率。合理做法是改造输入/解码并重新验收，或明确记为 UNSUPPORTED，保留覆盖缺口。

有向成本下，局部搜索不能直接套用只对对称问题成立的增量公式；虚拟节点等建模变换应验明语义等价。整数化则需披露误差、资源的保守处理和可能丢解的风险，由原参数 checker 验收，不宣称与浮点原题完全等价。库原生“支持某功能”不等于当前适配器已经支持该功能，最终以公开输入回读、独立 checker 和反例测试为准。

### 6.6 神经算法要单独交代训练与推理

神经方法至少分成三类条件：公开权重直接推理、仅用本 benchmark 开发分区训练/微调、神经模型再加传统搜索。三类不能合成一行成绩。

每个条件应记录架构/代码版本、权重摘要、训练数据和预训练暴露是否已知、训练规模、训练随机种子、训练算力/时间，以及推理时的解码策略、候选数、搜索秒数、设备、显存和运行时间。训练成本与每题推理成本分开报告；“一次前向很快”不能掩盖大量离线训练或测试时采样。

跨城市训练必须遵守城市分区，不能用测试城市生成训练题。组合实验可使用明确登记的同底座开发池，但不能把它同时算作严格跨城市条件。超参数、checkpoint、解码预算和约束修复器在验证集上选择，冻结后只做测试；研究者私有构造解不是可直接领取的训练答案。若需要训练标签，应独立生成并登记可用的开发参考解及其性质。

候选生成后附加传统 repair/search 是可评测的混合方法，但必须作为独立条件计时，并保留原神经输出的有效率。不能用隐藏修复把纯神经方法的失败抹掉。对 N19/N49 取送题与 N20/N50 完整节点题，padding、mask、角色和请求映射也需要明确验收。

### 6.7 跨方法公平比较的统一规则

1. **同题同语义**：保持同一底座、原始边量、任务目标与约束；传统/神经算法接收对应机器输入，LLM 接收登记的题面表示，Model 不公开预期 Scenario。表示差异单列，不替换成本、不删除规则，不读私有证据。
2. **覆盖与质量同时展示**：一张全任务表展示支持/不支持、完成率与可行率；另一张共同支持子集表比较质量。不能只留下每个方法擅长的题再直接排名。
3. **算力与预算分开列**：CPU、GPU、线程和内存，建模、推理、搜索及后处理时间分别记录。CPU 秒、GPU 秒和 token 不直接换成同一种“等算力”；可同时提供固定墙钟档及质量—时间曲线。
4. **同等总搜索机会**：一次调用、多起点、多个 seed、beam/sampling、best-of-k、repair 都计入该条件预算。历史定制搜索器的三个种子提供了更多总预算，不能解释成与别的方法一次运行预算相等；其混合池质量结果已暂缓公开。
5. **精确方法还看界**：除路线质量外，报告证优率和 primal/dual bound。整数近似模型上的最优终止，不自动授予原始浮点问题 EXACT。
6. **失败留在分母**：unsupported、无 incumbent、超时、OOM、传输失败、无效格式、约束违反和超预算分别保留，未执行另列。任务不可行只能凭规定证据判定。
7. **训练与推理解耦**：神经算法披露训练投入，LLM 披露服务/权重身份的不确定性，外部预训练暴露不明要保留未知，不假装具有同样训练预算。
8. **不混不同轨道**：Direct、Model、神经+搜索、工具 Agent、当前/未来快照各自成表；在共同下游目标上比较时同时披露上游信息与资源差异。
9. **控制参考池偏差**：BKS 记录来源、预算和版本。入池算法对自身 BKS 的 gap 有偏向，应披露池内比较，并在可能时补独立/留方法参考或可信最优界。
10. **按相关结构统计**：同底座派生题、嵌套规模、同题种子和重复调用不能当独立样本；先按题汇总，再按城市/父组或城市/日期报告，样本不足时不做普适排名。

### 6.8 全方法测评的执行与验收任务

完整 baseline 工作还需要三个明确交付，不能用“强基线已接入”概括完成：

- **方法登记表**：给每个候选明确实现、版本、许可、权重、设备需求、支持集合、预训练/训练条件及可复现入口，状态为已测、待测、不支持、实现不可得或资源条件未满足。
- **分层执行表**：在训练题上验接口，在验证题上选择设置，然后冻结题单、随机性、重复数、资源与停止规则；对登记的每个方法跑完全部合格测试条件，或保留明确的未完成原因。现有测试结果不用于反向挑方法、删题或调设置。
- **完整结果表**：逐方法/问题块/规模/城市/紧度展示计划、完成、支持、可行、质量、证优和资源，另给共同支持比较、失败分布与重复稳定性。只有所有登记条件都有终态或明确排除理由，才称该版本方法覆盖已完成。

当前的主要缺口是神经方法尚未形成已验收的正式条件，多类启发式尚未独立接入，以及外部工具仍缺统一预算下的完整横向表。下一阶段需要把这些作为主工作包，与补 reference、LLM 和动态实验共同推进。
