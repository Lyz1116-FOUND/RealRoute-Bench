# Method coverage and admission plan

The following is a planned coverage taxonomy, not a claim that every method has been run. The custom heuristic remains withdrawn from public results.

## 8 Baseline 体系：机制、适用范围与全方法覆盖

### 8.1 “能测的都测”如何成为可执行要求

目标覆盖精确、构造启发式、局部搜索、元启发式、神经构造、神经改进、LLM 与混合系统。不能只列方法名，必须对每个候选明确版本/权重/实现身份、支持的有向成本与约束、数据暴露、训练与推理预算，以及独立验收结果。允许方法只支持某些任务，但 UNSUPPORTED 进入覆盖统计，不靠去掉约束扩充成绩。

“全方法”是持续扩展的研究范围，不是当前已经跑完的事实。当前先保证各范式有可审计代表，再按公开实现和实际可运行性扩展。对没有成熟实现或不能保持任务语义的方法，记录不准入原因和待适配工作，不能把无法运行的名字列成已完成对照。

| 范式 | 代表及核心机制 | 当前状态 | 正式比较仍需完成 |
|---|---|---|---|
| 精确算法 | HiGHS MILP；Gurobi；小规模 DP | HiGHS 已执行；Gurobi 旧先导；DP 诊断 | 新 reference 池、版本/预算和原始证据 |
| 构造启发式 | 最近邻、插入、节约、regret insertion | 自研 greedy 已执行，范围有限 | 多起点、强插入及统一成本计量 |
| 局部搜索 | relocate、swap、2-opt/2-opt*、片段编辑 | greedy 部分 relocate；旧 ATSP 有向编辑 | 各原子可行邻域与增量计价验证 |
| 元启发式 | GLS、HGS、ILS、SA、禁忌、LNS/ALNS | OR-Tools/PyVRP 适配及小样；自研 LNS 撤下 | 有出处实现、支持矩阵、种子和全量运行 |
| 神经构造 | Attention Model、POMO、MatNet/URS | 旧方法线有模型；新题库未全量接入 | 有向矩阵输入、约束掩码、训练分区 |
| 神经改进 | 学习邻域、NeuroLKH 类候选引导 | 列入计划，未完成当前正式测评 | 检查稀疏候选是否改变可行域 |
| LLM | Direct、声明式 Model、受控工具链 | Spark 小样；Qwen/GLM 开发记录 | 锁模型身份、匹配预算、扩题复测 |
| 混合方法 | 神经/LLM 候选＋solver/repair | 设计及局部组件 | 拆解生成、修复、求解的独立贡献 |
| 时间方法 | Static、Reactive、预测、记忆、JEPA | 接口与历史开发实验 | 新序列正式生产运行、因果与预算确认 |

### 8.2 构造与局部搜索为什么仍重要

最近邻每一步选当前局部最便宜的可行下一点，计算轻，但容易陷入短视。插入法评价把未访问点加入各路线各位置的边际成本，可自然结合车辆与窗口；regret 则优先处理“最佳插入与次佳插入差较大”的困难客户，避免其廉价位置被抢。节约法从多个短路线合并，利用合并前后的成本减少量。不同机制的失败模式不同，不能用一个最弱 greedy 代表全部传统算法。

当前 greedy 只支持必访、min_total_cost/min_makespan 与 capacity、time_window、service_time、vehicle_limit、route_duration、distance_limit、cost_budget 的适当组合；可选访问与复杂关系并非全支持。容量加时间窗场景使用按 deadline 排序的联合插入，遍历车辆与位置并做公开约束检查；某些配送配置含专门分组过程。无约束闭合场景还做两轮 relocate，并对有向总代价完整重算。该实现是可解释弱基线，不是文献中全部构造/改进方法的充分代表。

有向路线的邻域必须谨慎。relocate 保持片段内部方向，delta 可以由少量边替换求得；对 ATSP 做 2-opt 反转则同时改变所有内部边方向，不能沿用对称 TSP 只改四个端点的公式。加入时间窗、取送或车辆关系后，还须检查受影响后缀状态和关系。后续要求局部增量计算与 checker/暴力重算在小实例一致，才能用它支撑大规模搜索结果。

### 8.3 外部 OR-Tools 与 PyVRP 的实际适配

元启发式各有不同的跳出局部最优机制：SA 按温度允许一定概率的劣化，禁忌搜索短期禁止回撤，ILS 对局部最优做扰动和重启，HGS 维护种群并结合局部搜索与多样性。它们需要明确接受规则、参数和预算，不能由一个方法替代整个谱系。

OR-Tools Routing 的构造加 guided local search 通过改变局部搜索的评价惩罚帮助跳出停滞[6]；最终仍按原目标计价。现有适配器面向全部必访的 min_total_cost，覆盖容量、窗口、服务、时长、距离/成本资源、车辆上限，以及取送和车辆/先后关系，并处理三种终点模式。支持的是这段适配实现的能力，不是产品所有功能的总览。

PyVRP 代表混合遗传与局部搜索范式[7]。现有适配限定必访与 min_total_cost，支持仓库配送容量、时间窗、服务时长、异构/多仓库及闭合/固定终点；尚不支持自由终点、取送及一般关系、可选收益罚金和其他资源目标。其坐标字段为接口占位，distance 字段承载当前目标成本，不自动具有物理距离语义，因此不能把未适配的 distance_limit 当作已经支持。

历史安装记录 OR-Tools 9.15.6755、PyVRP 0.14.0。输入按 1000 比例转整数：目标四舍五入，资源消耗与上限按保守方向取整。这样可以减少资源超限，但会改变目标排序或排除边界可行解；不据此授予原连续任务的最优性或不可行证明。候选最终回到原始浮点矩阵和独立 checker。OR-Tools 元数据还明确 seed_applied=false，不能把不同 seed 标签当成真实独立随机重复。

原静态题库的能力筛选为 OR-Tools 744 题、PyVRP 384 题；这是计划支持数，不是全量运行完成数。历史 51 道训练题、3 城、1 秒预算的五方法诊断共有 255 个记录，其小样、训练分区和短预算性质不支持正式排名。外部参考补跑仍需按冻结清单执行并验证收据。

### 8.4 LNS/ALNS：思路合理，具体实现不能借用论文身份

LNS 的通用原理有明确来源：从当前解中移除一部分访问，再用约束传播或插入重建被破坏部分，搜索尺度大于单次小邻域移动。Shaw 的大邻域思想与 Ropke–Pisinger 的 ALNS 是可引用的代表[4,5]。ALNS 的关键还包括多个 destroy/repair 算子的自适应选择及相应接受机制；不能把所有“随机删点再插回”都称作复现某篇 ALNS。

本地被质疑版本的实际机制为：随机移除约 15%–40% 客户、按位置候选计算 regret、只接受改善、每 5 轮重启。它没有验证为权威算法的完整实现，也没有对应的自适应算子权重或退火接受过程。其 regret 候选来自所有位置，亦不等同于某些文献按不同路线定义的 regret。通用思路合理，但性能、实现正确性和公平性必须靠具体实现证明，不能由“LNS 有论文”一并担保。

已从公开结果移除该方法的 17 行先导记录，保留其他方法 51 行，并将依赖旧池的相对 gap 留空。内部历史结果与运行日志保留用于追溯；正在运行且包含它的旧冻结批次只报告作业计数，不自动进入新公开 reference 池。后续可选有明确版本和出处的实现，或把它如实命名为自研 destroy–repair heuristic，先做语义与算法验证再决定准入。

### 8.5 神经算法：学什么、怎样公平比较

神经构造方法把路线表示为自回归策略：

$$
p_\theta(\pi\mid\mathcal I)=
\prod_{h}p_\theta(a_h\mid\mathcal I,a_{<h},m_h),
$$

m_h 是根据当前资源和访问状态生成的可行动作掩码。Attention Model 用编码器和注意力解码器建模组合结构[2]；POMO 通过多个起始解轨迹和共享基线改善策略梯度估计与搜索机会[3]。典型训练目标为期望路线代价，REINFORCE 估计为：

$$
\nabla_\theta J=
\mathbb E\left[(C(\pi)-b)\nabla_\theta\log p_\theta(\pi\mid\mathcal I)\right].
$$

损失形式通用，不意味着现成欧氏权重能处理任意有向矩阵和 14 原子。必须明确 cost encoder、车辆状态、关系掩码、终止条件与训练分布。坐标旋转/镜像增强保持欧氏距离，却不自然适用于任意有向成本；合法节点置换须同步变换所有矩阵、属性和关系。POMO 轨迹数、采样数和增强次数都属于搜索预算。

神经改进方法从完整可行解出发，学习选择邻域或评价改动；神经搜索混合可预测候选边来引导传统搜索，NeuroLKH 是代表[8]。其优势可能来自降低搜索成本，而非纯神经直接解题。若稀疏候选删除了原可行边，需要报告是否有回退和是否改变问题；若作成本重参数化，需要验证原始路线评分与约束保持。现阶段它们属于应测方法，尚未在当前完整题库完成接入和排名。

### 8.6 LLM 与工具系统的预算边界

Direct 输出路线，Model 输出声明式 Scenario 后交给固定 solver，工具系统还可能包含检索、代码或多轮修复。这些系统的能力构成不同：Model 的好解可能主要来自后端精确求解；repair 的收益可能主要来自额外搜索。比较应同时设“同 backend”“同 token/调用数”“同总时间”对照，记录解析、语义、求解、checker 各阶段。

端到端能力可作为一种产品指标，但不能把工具链的最优性归给 LLM 推理本身。当前基准的受控 Model 轨不执行任意 Python；如后续引入代码生成，必须作为独立轨道定义执行环境与资源边界，不混入现有声明式结果。
